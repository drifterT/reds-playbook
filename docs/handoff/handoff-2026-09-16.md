## 1. この作業の目的

対象は小学4〜6年生、10〜12歳の少年野球選手。

原典『バッティングメカニズムブック 改善編』の写真、動作説明、狙い、注意点を軸にし、
外部のバイオメカニクス、医学、ユース指導、Driveline等の実務情報を補助として照合し、
現場で反復する基盤ドリルを厳選する。

教えたい中心要素は次の4点から始まった。

1. 体重移動
2. 引き手、つまりボトムハンド側の肩によるスイング始動
3. トップの作り方
4. 割れの作り方

その後、オーナーが実際に約10名へ試験指導した結果、4点を個別に並べるだけでは足りず、
次の共通基盤を最優先にする必要があると分かった。

- 踏み出し足を投手側へ運ぶ
- 後ろ腰を投手方向へ直進させるように体重を移す
- 踏み出し足側の股関節付近で体重を受ける
- その股関節を回転の支点として上体を素早く回す
- 胸の回転に伴い、ボトムハンド側の肩からバットを導く

最終成果物は監督・コーチ向けの6〜8枚程度のスライドPDFを想定している。
1枚あたりの本文量は約300字が上限。人は一度に大量の説明を記憶できないため、
原典や調査結果を網羅する資料ではなく、現場で使う重要項目だけを残す。

## 2. 現場条件と、絶対に戻してはいけない前提

- チーム練習は週2回、土曜日と日曜日。
- 夏季は概ね8:00〜18:00、冬季は概ね9:00〜17:00。
- 従来の打撃練習は最大約2時間で、正面トス、フリーバッティング、シートバッティングを含む。
- 今回の基礎技術ドリルは、それらを置き換えずに追加する独立モジュール。
- 全体は約20名。運用案では1グループ6〜7名、コーチ2名を想定していた。
- 当初は20分×2枠、計40〜45分程度を検討したが、最終的な時間配分、人数、道具数は監督・コーチが決める。
- 全員が毎回同じ基盤ドリルを反復する。個人レッスンのような「1日目、2日目」や習得段階別の進級方式を主構造にしない。
- 実打撃は置きティーまで。正面トス以降は既存メニュー側で扱う。
- 「速く強く振る」は既存練習で確保済みなので、この資料の主目的ではない。
- 原典にある全ドリルをやらせるのではない。多数のドリルから目的、再現性、安全性、教えやすさを照合して厳選する。
- 「原典の一部を省略している」という事実自体は批判点にならない。省略は前提であり、問うべきは採用したドリルが最適かどうか。
- 外部資料を原典と単純比較しない。原典の各ドリルにある細かな姿勢、動作、狙い、失敗例を、外部のバイオメカニクス、医学、成人・ユース指導の知見と要素単位で照合する。

## 3. 情報源の優先順位

内容判断では次の順を守る。

1. オーナーの現場観察と明示指示
2. 原典PDFの本文と写真
3. 実際のプロ選手のスロー映像
4. 一次研究、公式組織の資料、Driveline等の一次コンテンツ
5. Perplexity、Gemini、Claude、Codexの整理

AIの要約は正本ではない。特に「海外で広く使われている」「万能ドリル」「完全に一致」などの
強い表現は、一次資料を確認しない限り資料へ入れない。

外部資料の役割は次のとおり。

- 原典の狙いを補強する
- 成長期の注意点を補う
- コーチの観察語、短い声かけ、代償動作の見分け方を補う
- 原典に同一手順がないチーム独自ドリルの位置づけを明示する

外部資料で原典を置き換えない。また、成人・大学選手向けの大きな分離、特殊バット、
高出力回転を10〜12歳へそのまま転用しない。

## 4. 成長期の安全に関する共通ルール

- 腰を反らせて回旋量を作らせない。
- 「腰を固定して上だけを最大限ねじる」と教えない。
- 「前脚の壁」「膝をロック」「ガチッと止める」を主要な選手向け表現にしない。
- 前足のつま先と膝が同じ方向を向くかを見る。
- 膝が内側へ崩れた状態で、無理に大きな割れを作らせない。
- 割れは角度の大きさを目標にしない。踏み出しとバットを引く動きの時間差として小さく扱う。
- 頭から投手側へ流れたら、動作量を小さくするかバットなしへ戻す。
- 痛み、しびれ、腰の反りが出たら、軽くする、小さくする、バットを外す、中止の順で対応する。
- バットありの全員同時動作を行う場合、十分な間隔を確保する。
- 1回のフィードバックは1項目。未経験コーチが自己流の言い換えを増やさない。

## 5. 資料表現の確定ルール

対象コーチの大半は、野球経験がほとんどない、または全くない父親コーチ。
原典を持っているのはオーナーのみ。他の指導者はこの資料だけを読む。

したがって、各スライドには少なくとも次を持たせる。

- 何のために行うか
- 開始姿勢
- 動かす順序
- 終わりの形
- 選手にそのまま言う短い一言
- できているときに見える形
- 崩れたときに戻す基準

語彙と表記は次のとおり。

- 子ども向け本文では「骨盤」より「腰」、「胸郭」より「胸」を優先する。
- 「下の手／上の手」は使わない。
- 「引き手（ボトムハンド）」「押し手（トップハンド）」を使う。
- 方向は右打者基準で、投手方向、一塁側、三塁側。左打者は左右反転。
- 「キュー」「ロードポジション」「ネットを向く」など、未経験コーチが説明できない語を避ける。
- 選手に伝える一言は一つ。20字前後を目安にする。
- 「感覚を得る」「関係を作る」「時刻をそろえる」など、外から判定できない抽象語に逃げない。

スライド上に原典ページや出典を載せない。オーナーから明示的に「出典はいらない。原典は誰も見ていない」
と指示があった。必要なら制作者向けノートや別紙に保持するが、選手・コーチ向け画面には出さない。

## 6. 画像全体に共通する確定ルール

### 6.1 人物の統一

ここが現在の最重要事項。

- スライド2の人物を人物・体型・服装・画風の正本にする。
- 以降の全スライドで同じ人物を使う。
- 同一スライド内だけでなく、スライドをまたいで体型、髪型、顔の処理、服装、線・質感を変えない。
- スライド3の現行画像は人物が異なるため不採用。
- 新規画像生成では、スライド2画像を第1参照画像にする。
- 既存スライド3画像は、動作のコマ割りを伝える第2参照画像としてのみ使用できる。

### 6.2 人物の見た目

- 顔はのっぺらぼう。目、鼻、口を描かない。
- 表情をつけない。
- ユニフォームを着せない。
- ヘルメット、帽子、スパイクを描かない。
- 黒のノースリーブ練習着、黒の短パンを基本とする。
- 足部と接地を見せるため裸足を基本とする。
- 筋肉や骨格は読める程度に自然に描くが、骨を写実的に露出させない。

### 6.3 教材として見せる線と印

- 背骨は細い青線で示す。
- 腰・骨盤の向きはマゼンタ系の線で示す。
- 支点となる股関節は黄色の丸で示す。
- 直進は直線矢印、回転は曲線矢印で区別する。
- 線や丸は動作理解のための模式記号であり、解剖学的な骨の写実画にはしない。
- 人物が主役。矢印や印が人物を隠さない。
- 背景は白。黒背景は見づらいというオーナー指摘があり不採用。

### 6.4 画像に入れないもの

- 出典
- URL
- 長い説明文
- ロゴ
- ウォーターマーク
- 成人向けの角度や出力数値
- 不要な装飾

## 9. スライド3の経緯、正しい内容、現状の不備

### 9.1 最初の誤り

最初の画像は右打者の動きなのか左打者の動きなのか分かりにくく、
右打者を想定しているのに右足側へ体重移動していた。

右打者の踏み出し足は左足。体重は右腰側から左腰・左股関節側へ移動する。
また、斜め視点では横移動幅が読めないため、椅子を使った正面視点が必要。

### 9.2 2つのドリルを混同しない

スライド3には目的の異なる2段階がある。

#### A. 左右の可動域を広げるストレッチ

- 椅子の背を両手で持つ。
- 両足を肩幅より広くする。
- 脚のつけ根から上体を前へ倒す。
- 腰を左右へゆっくり動かす。
- 移動方向の腰の側面が、その側の足より外へ出るまで動かす。
- 左右とも行う。
- これは可動域を十分にするためのストレッチ。

この大きな横移動幅を、そのまま打撃の体重移動として使わない。

#### B. 右打者の体重移動と回転

- 右腰側にある体重を左へ移す。
- 左腰・左股関節の真上まで移動する。
- ストレッチのように足の外まで大きく出さない。
- その位置で椅子をどかす、または椅子から手を離す。
- 椅子を外しても体重を右へ戻さない。
- 左足側の股関節で体重を受ける。
- 左股関節を支点として回転する。
- 右腰、つまり後ろ腰を投手方向へ進める。
- 左膝を棒のように固定しない。

オーナーの説明を短くすると、

> 右腰から左腰、左股関節の真上まで移動し、その状態で椅子をどかし、
> 体重が左股関節にある状態で、それを支点として回転する。

### 9.3 画像の視点

- 正面から描く。
- 右打者の左足・左股関節は、見る側の右に位置する。
- 左股関節を黄色の丸で示す。
- 右から左への横移動は、見る側では左から右へ進むように見える。
- 斜め視点へ戻さない。

### 9.4 現在の構成案

上段:

- 左へのストレッチ
- 中央
- 右へのストレッチ

下段:

- 右腰側へ荷重して椅子を持つ
- 左股関節へ移動する
- 椅子を外しても左股関節上を保つ
- 左股関節を支点に回転する

### 9.5 現行画像の問題

現在保存されている次の2画像は、上記構成を説明するために作った。

- `hip-mobility-stretch-front-v1.png`
- `right-hitter-left-hip-sequence-v1.png`

しかし、**スライド2と人物が違う**。髪型、体型、顔の形、レンダリングの質感が一致しない。
オーナーから「だんだん仕事が雑になっている」と指摘された直接原因である。

加えて、現行画像には次の確認余地がある。

- 上段のストレッチで、腰の側面が足より外へ出たことが画像だけで十分読めるか。
- 下段2コマ目で、左腰が左股関節の真上まで移動したことが明確か。
- 下段3コマ目で、椅子を外した後も左側荷重を維持しているか。
- 下段4コマ目で、左膝をロックせず左股関節を支点に回っているか。

人物を直すだけで自動的に合格にはならない。4点を再確認する。

## 11. 画像生成で起きた失敗と再発防止

### 11.1 人物を毎回ゼロから生成した

同じ「黒い服、のっぺらぼう」と書いても、画像モデルは別人を生成する。
文章だけのスタイル指定では、スライドをまたぐ人物統一を保証できない。

対策:

- スライド2画像を毎回第1参照画像にする。
- 「同じ人物」と書くだけでなく、体型、髪型、顔処理、服装、裸足を不変条件として反復する。
- 既存スライド3画像を使う場合は、第2参照画像としてポーズだけを借りると明示する。
- 生成後に人物比較を行い、違えば採用しない。

### 11.2 動作を一つの画像に詰めすぎた

画像モデルは、右足・左足、前足・後ろ足、支点、移動方向を入れ替えることがある。

対策:

- 右打者の左足が見る側の右にあることを明記する。
- コマごとの状態を文章で分ける。
- 参照画像上の黄色い支点を同じ位置に保つよう指定する。
- 動作内容をオーナー確認してからスライドへ組み込む。

### 11.3 見た目を優先して技術内容を誤った

スライド1ではインパクト位置が捕手寄り、ボールの高さが不連続など、
見た目は整っていても打球方向・時間順序が成立しない画像があった。

対策:

- 接地、ボール位置、バット位置、支点をコマ間で確認する。
- 前後のコマを連続動作として見る。
- 技術内容が誤っていれば、画質が高くても不採用にする。

### 11.4 画像生成とスライド制作を同時に進めた

不採用画像をレイアウトへ組み込み、後から差し替えが発生した。

対策:

1. 単体画像を生成する。
2. オーナーが人物と動作を確認する。
3. 承認された画像だけをスライドへ配置する。

## 12. リポジトリに保存した画像生成コード

### 12.1 ファイル

- `scripts/codex/generate_batting_images.mjs`
- `scripts/codex/batting-image-jobs.json`
- `scripts/codex/README.md`

### 12.2 方式

OpenAI Image APIをNode.jsの標準 `fetch` で呼ぶ。npmパッケージは不要。

モデルは会話中に指定されたGPT Image 2を維持し、再現性を少しでも高めるため
`gpt-image-2-2026-04-21` をmanifestで固定した。

新規生成ではなく編集エンドポイントを使い、入力順を次に固定する。

1. スライド2の人物・画風正本
2. スライド3の不採用画像。ポーズとコマ割りの参考のみ

GPT Image 2は画像入力を高忠実度で処理するため、`input_fidelity` は指定しない。

### 12.3 重要な制限

今回の会話ではCodexデスクトップの内蔵画像生成ツールを使った。
内蔵ツールの実行をそのままリポジトリから再生する公開コードはない。

保存したAPIコードは、合意したプロンプト、モデル、サイズ、品質、参照画像、出力先を
再現可能にするためのもの。過去の内蔵ツール呼び出しをバイト単位で複製するものではない。

また、画像生成は非決定的。同じプロンプトでも同じピクセルにはならない。
そのため、生成結果を人が確認する工程を外さない。

実行には `OPENAI_API_KEY` とAPI利用権限が必要。キーをリポジトリへ保存しない。
